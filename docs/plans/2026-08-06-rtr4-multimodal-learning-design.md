# RTR4 多模态学习系统设计

日期：2026-08-06

## 目标

构建本地 Web 应用。首个垂直闭环覆盖《实时渲染第四版》中文版第 5 章（PDF 第 104–154 页）。系统必须保留并理解正文、数学公式、图片、图注、代码以及它们之间的版面关系，并提供：

- 逐章节课程；
- 带页码和原始区域引用的问答；
- 公式推导、变量解释与数值示例；
- 图片和示意图分析；
- GLSL、HLSL 或 WebGPU 代码案例；
- Shadertoy 等外部演示链接；
- 练习、测验和错题记录。

## 约束

- 运行方式：本地解析与缓存，复杂公式和图片按需使用云端视觉模型。
- 本机硬件：RTX 3050 8 GB、32 GB RAM、Intel i5-12400F。
- 当前未配置云端视觉 API Key，首版必须支持纯本地降级。
- 默认不向云端批量上传整本书，只发送显式选择或低置信度区域。
- 首版只覆盖第 5 章，验证后再逐章扩展。

## 技术选择

### 文档解析

采用解析器适配层：

- 默认：MinerU Pipeline。本地运行，支持 Windows、CPU/GPU、公式 LaTeX、图片、表格、坐标和结构化 JSON。
- 对照：Docling。用于同页 A/B 测试和数据模型验证。
- 后备：PaddleOCR-VL 或云端视觉模型。只处理低置信度公式、复杂图表或解析异常页面。
- 不采用 pdf-rs 作为主解析器。它能快速读取 PDF，但当前版本没有适合本任务的高级版面和公式提取能力。

### Web 应用

- 前端：React + Vite。
- PDF 阅读：Mozilla PDF.js。
- 公式渲染：KaTeX。
- 后端：FastAPI。
- 本地状态：文件系统保存不可变阶段产物；SQLite 保存索引、用户进度和问答记录。
- 检索：SQLite FTS5 + 本地多语言向量嵌入；先精确过滤章节/页码，再混合排序。

## 统一文档模型

实体层级：

```text
Book -> Chapter -> Page -> Block -> Asset
                         -> Relation
                         -> DerivedContent
```

Block 类型至少包括：

- text
- heading
- formula
- figure
- figure_caption
- table
- code
- list
- page_header
- page_footer

每个块保存：

- 稳定 ID；
- PDF 页码；
- 归一化和原始坐标；
- 原文、LaTeX 或 HTML；
- 原始裁剪图；
- 解析器、模型、版本和置信度；
- 与图注、公式编号、正文引用、章节标题的关系；
- 原始解析结果引用，确保可审计。

示例：

```json
{
  "id": "p105-equation-5.1",
  "type": "formula",
  "page": 105,
  "bbox": [98, 742, 891, 823],
  "latex": "c_{shaded}=...",
  "number": "5.1",
  "image": "blocks/p105-equation-5.1.png",
  "relations": [
    {"type": "explained_by", "target": "p106-paragraph-2"},
    {"type": "uses_figure", "target": "p105-figure-5.3"}
  ],
  "source": {
    "parser": "mineru",
    "confidence": 0.91
  }
}
```

## 处理流水线

所有阶段离散、幂等、可缓存、可单独重跑：

1. `register`：登记 PDF、SHA-256、书籍元数据和章节页码。
2. `render`：渲染第 104–154 页并保留页面尺寸映射。
3. `parse`：运行解析器，保存未经修改的 Markdown、JSON 和资源。
4. `normalize`：转换为统一文档模型。
5. `validate`：检测缺失公式、异常字符、越界坐标、孤立图注和关系错误。
6. `enrich`：只处理低置信度公式、图片和复杂页面；缓存结果。
7. `index`：建立全文、公式、图片说明、页码和向量索引。
8. `teach`：生成课程、概念关系、练习和代码案例。
9. `serve`：FastAPI 暴露书籍、页面、块、课程、检索和问答接口。
10. `ask`：混合检索，生成带来源回答。

每阶段保存：输入清单、输出清单、配置、工具版本、开始/结束时间、错误和状态文件。

## 教学生成

内容组织层级：

1. 直觉解释；
2. 数学定义与变量；
3. 公式推导和边界条件；
4. 对应图形学意义；
5. Shader 或 CPU 代码实现；
6. 可运行数值例子；
7. 常见错误；
8. 练习与测验；
9. 原书页码、公式和图片引用；
10. 可选外部演示链接。

任何教学断言必须关联一个或多个原始块。无法找到可靠来源时，系统必须说明不确定性，不得编造引用。

## Web 界面

桌面宽屏布局：

- 左侧：PDF.js 原页、页码导航、搜索结果和块高亮层。
- 右侧：课程、概念解释、KaTeX 公式、图像分析、代码和练习。
- 底部或抽屉：带引用问答。

交互要求：

- 点击教学引用，跳转并高亮 PDF 对应区域。
- 点击 PDF 公式、图片或段落，打开对应讲解。
- 回答显示页码、块类型、原文摘要和定位按钮。
- 云端视觉未配置时，界面明确显示降级状态。
- Shadertoy 首版使用外链，不依赖其 API 或 iframe。

## 错误与降级

- MinerU 不可用：保留 PDF.js 阅读和现有文字层。
- 公式失败：保存裁剪图并加入待校验队列。
- 图片理解失败：显示原图和图注，不生成猜测说明。
- 云 API 未配置：运行本地解析、索引和基础问答。
- 回答缺少来源：拒绝确定性断言，展示相关页面。
- 重跑失败：保留旧产物，新产物写入临时目录，成功后原子替换。
- 云端调用：按输入图片哈希、提示词版本和模型版本缓存。

## 验收标准

解析：

- PDF 第 104–154 页全部可浏览。
- 公式 5.1、5.2 能显示 LaTeX、原始裁剪和页码。
- 图 5.2、5.3、5.9 能关联图注与正文引用。
- 坐标可在 PDF.js 上正确高亮。

检索与问答：

- 20 个代表问题至少 18 个命中正确页面。
- 回答引用准确率目标不低于 95%。
- 无来源问题不得生成伪引用。

教学：

- 不改变原公式含义。
- 能从直觉、数学和实现三个层级解释代表概念。
- 代码案例包含预期结果和验证方式。
- GLSL 示例通过语法编译检查。

Web：

- 讲解可跳回原始 PDF 区域。
- 无云 API 时仍能完成阅读、检索和基础问答。
- 阶段失败和降级状态对用户可见。
