# 全书精读架构与实施路线

用户已批准：全书建立结构，逐章加工、审校和发布。2026-09-24 的计划只作为伴读 UI 子计划，不再定义产品范围。

## 架构

1. 书籍证据：书籍版本、全书目录、章节/小节区域、PDF与印刷页码、原始来源块。
2. 处理流水线：全书基础提取，逐章多模态处理；独立任务、可恢复、资源预算、校验与不可变产物。
3. 知识组织：概念、前置关系、跨章引用与后续应用；初期复用 SQLite，不引入图数据库。
4. 教学发布：证据整理→大纲→草稿→自动检查/人工审校→发布。原书事实、教学补充和工程近似分开。
5. 伴读：全书任意页可读，当前位置关联讲解，跨章旁证可返回；未覆盖页不展示无关课程。
6. 学习记录：独立于教学版本保存位置、笔记、自测与待复习；内容升级不能丢学习记录。

原书可读、解析覆盖、精讲发布、个人学习进度分别记录，不合成一个完成百分比。新增章节应是内容和配置操作，而不是复制前后端逻辑。

## 首批实施（本轮）

- A. 全书页面 API：范围由 BookManifest.page_count 决定；未解析合法页返回明确的 not_parsed 状态与空块，不伪造解析内容；损坏产物仍报错。
- B. 阅读器降级：使用不依赖章节的页面 API；未解析提示与 PDF 渲染分开。
- C. 书籍驱动导航：从书籍 API 加载总页数和已登记目录；全书翻页、边界校验、目录跳转。未覆盖精讲时移除旧课程。既有第五章入口暂作迁移兼容，不宣称完成通用教学发布。
- 每步先写失败测试、验证失败，再实现和回归；批次完成提交、推送。

## 后续批次

1. 从 PDF 书签/目录页提取全书目录候选，校对章节起止和印刷页码；新增章节/节不能猜测。服务端统一课程目录与书籍作用域，去除既有兼容入口。
2. 逐章任务与覆盖清单：排队、暂停、失败重试、磁盘路径/预算；沿用已有 manifest/build 机制，不再建重复流水线。
3. 教学契约与发布状态：选跨章节的数学、图片、算法/工程样本测试同一契约；加入引用审校、计算测试、代码验证。
4. 完整伴读状态机、跨章依赖、证据卡、自测与恢复；问答支持明确章节和全书范围。
5. 按用户阅读优先级逐章交付到全书。每章按知识点覆盖清单验收，保留未解决事项。

## 验收

首批：第1页、第五章已解析页、第903页都能导航；无解析页显示提示而非PDF失败；越界被拒绝；损坏解析不能伪装未处理；加载书籍失败可重试。回归既有课程与PDF文档复用。

全书系统：新增章节不改UI逻辑；失败重跑不影响已发布内容；跨章引用准确；原文和教学版本可追溯；关键公式/图/算法逐项复核。进度必须明确区分系统能力与实际全书内容覆盖。
